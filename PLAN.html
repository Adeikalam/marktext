MarkText Git Integration Plan

Add Azure DevOps–focused Git integration to MarkText via a main-process Git service that spawns the system git CLI (Git 2.x+ on PATH, or MARKTEXT_GIT override), a simplified Source sidebar panel, PAT auth stored in OS keychain, automatic background fetch with clear sync status, diff review, and one-click commit/push/pull flows aimed at non-technical documentation writers.

Goals and constraints

MarkText today has no Git integration — one folder per editor window (src/renderer/src/store/project.ts), sandboxed renderer, and main-process IPC for external tools (ripgrep, uploader). This plan adds documentation-centric version control without exposing Git jargon.

In scope (initial release)

  • Clone an Azure DevOps repo by URL + PAT
  • Auto-fetch remote changes; clearly show when local is behind
  • One-click Get latest changes (pull) with plain-language conflict guidance
  • Review diffs per file
  • Commit and push to the current branch

Explicit choices

  • Auth: Personal Access Token stored in OS keychain via existing keytar in src/main/dataCenter/index.ts
  • Behind remote: Offer pull; guide user if conflicts occur (do not silently merge or block without explanation)

Out of scope for v1

  • Branch creation/switching UI (show current branch only in v1)
  • Merge conflict resolution inside the editor
  • SSH remotes, multi-remote repos, stash, rebase, cherry-pick
  • GitHub/GitLab-specific flows (Azure DevOps first; URLs remain generic HTTPS)

Why system git (not isomorphic-git): Native Git is faster on large repos, supports the full porcelain/plumbing surface MarkText needs (status --porcelain, pull --ff-only, rev-list), and avoids bundling a large JS Git implementation. Users install Git once (Git for Windows, Xcode CLT / Homebrew, or Linux packages) — same model as optional Pandoc. Override the binary with MARKTEXT_GIT for development.

Trade-offs to accept: Git must be installed and on PATH; show a clear git_not_found error when missing; Azure DevOps HTTPS + PAT injected via http.extraHeader on each network command.

Repo root detection: When a folder is opened, walk up from projectTree.pathname to find .git (supports docs in subfolders). Attach Git state to the repo root, not necessarily the opened folder.

Layer 2 — Main-process Git service

File layout

src/main/git/
  runner.ts       # Resolve git binary, spawn CLI, PAT config args
  service.ts      # Core operations (status, commit, push, pull, fetch)
  auth.ts         # PAT from keytar + http.extraHeader auth args
  clone.ts        # Clone wizard backend (git clone --progress)
  diff.ts         # Unified diffs via git diff
  porcelain.ts    # Parse git status --porcelain=v1 -z
  parse.ts        # Azure DevOps URL normalization, repo root walk
  errors.ts       # Map git CLI errors → user-facing codes
src/main/ipc/git.ts

System git setup (main process only)

  • Require Git 2.x+ on PATH (or MARKTEXT_GIT override, same pattern as MARKTEXT_PANDOC)
  • Spawn git via child_process.spawn — never run git in the renderer
  • Set GIT_TERMINAL_PROMPT=0 on every invocation to prevent interactive prompts
  • Surface git_not_found when the executable is missing

PAT authentication (auth.ts)

  • Storage: Extend DataCenter.encryptKeys with keys like git-pat-{hostKey} where hostKey = normalized host + org (e.g. dev.azure.com/contoso)
  • Usage: Inject PAT on network operations via -c http.extraHeader=Authorization: Basic … (empty username + token). Applied in runner.ts for clone, fetch, push, pull.
  • Never log PAT; never send PAT to renderer except masked indicator (“Connected as …”)
  • Never persist PAT inside .git/config or remote URLs in the repo
  • PAT scope guidance in UI: Code (Read & Write) for clone/push; link to Azure DevOps PAT docs

Azure DevOps URL handling (parse.ts)

Normalize user-pasted URLs:

  • https://dev.azure.com/{org}/{project}/_git/{repo}
  • https://{org}@dev.azure.com/{project}/_git/{repo}
  • Legacy https://{org}.visualstudio.com/...

Validate HTTPS only in v1; reject SSH (git@...) with friendly message.

Core operations (git CLI)

  • Status: git status --porcelain=v1 -z → parse in porcelain.ts; branch via git rev-parse --abbrev-ref HEAD
  • Ahead / behind: git rev-list --left-right --count HEAD...origin/<branch> after fetch
  • Auto-fetch: Renderer schedules periodic mt::git::fetch (default every 3 minutes when Git panel visible; every 5 minutes when hidden). Main runs git fetch origin, then emits mt::git::status-changed.
  • Diff: git diff HEAD -- <path> (untracked: git diff --no-index /dev/null <path>)
  • Stage / commit: git add then git commit -m … --author "Name <email>"
  • Push: git push origin <branch>
  • Pull (ff-only): git pull --ff-only origin <branch>; conflicts via git diff --name-only --diff-filter=U
  • Clone: git clone --depth 1 --single-branch --progress <url> <dest>

Hide .git from file tree

Update chokidar / tree building in src/main/filesystem/watcher.ts and src/renderer/src/store/treeCtrl.ts to ignore .git (similar to node_modules ignore).

Layer 3 — Renderer: Pinia store

New src/renderer/src/store/git.ts (setup store, like project.ts):

State

repoRoot, branch, syncStatus (ahead/behind), changedFiles[], isLoading, lastError, isRepo, hasPat, fetchTimerId

Actions

  • initForProject(pathname) — detect repo, load PAT status, start fetch interval
  • refresh() — status + sync counts
  • fetchRemote() — invoke fetch, then refresh
  • pullLatest() — invoke pull; on conflict set conflictFiles[]
  • publish(message) — stage all → commit → push (main “happy path”)
  • openDiff(path) — load diff into DiffView
  • stopPolling() — on project close / unmount

Hooks

  • Watch projectStore.projectTree → initForProject
  • After editor save success → debounced refresh() (300 ms)
  • Listen for mt::git::status-changed from main

Testing strategy

Unit tests (test/unit/specs/):

  • git-parse.spec.ts — Azure DevOps URL normalization
  • git-porcelain.spec.ts — status --porcelain → GitChangedFile[] mapping
  • git-errors.spec.ts — git CLI / HTTP errors → error codes
  • git-diff.spec.ts — unified diff via git diff

Integration tests: use system git in temp dirs end-to-end (init → add → commit → push to local bare repo). CI runners include Git preinstalled.

E2E: scripted local remote; verify sync banner when behind > 0.

Manual QA (Azure DevOps): clone private repo; edit → diff → share; two clients push/pull; simultaneous edit conflict message.

Security checklist

  • PAT only in main process + OS keychain (injected via http.extraHeader on spawn)
  • Clear PAT when user disconnects account
  • Do not write PAT to .git/config in plain text
  • Validate clone destination (no path traversal via repo name)
  • IPC: validate all paths stay within allowed directories
